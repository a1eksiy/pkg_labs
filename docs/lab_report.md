# Сопроводительная документация к лабораторной работе № 2

## Назначение

Программа извлекает метаданные растровых изображений из отдельных файлов и папок. В таблице представлены путь, фактический формат, размеры, DPI, глубина цвета, сжатие, статус и диагностическое описание.

## Библиотеки и архитектура

Интерфейс реализован на PySide6. Для экспорта используется стандартный модуль `csv`; для проверки CRC PNG — стандартный `zlib`. Для чтения метаданных не используются библиотеки декодирования изображений. `main.py` запускает приложение, `ui/` содержит окно и табличную модель, `scanner.py` организует обход и ограниченный пул потоков, `parsers/` содержит отдельные парсеры, `models.py` задаёт запись результата, `exporter.py` сохраняет CSV.

## Ручной разбор форматов

### BMP

Сначала проверяется сигнатура `BM`. Затем читаются BITMAPFILEHEADER и DIB-заголовок. Извлекаются ширина, высота, planes, глубина цвета, код сжатия, размер палитры и смещение пиксельных данных. Для индексированных BMP палитра обычно содержит `2^bpp` записей, если поле `colors_used` не задаёт другое количество. В старом DIB-заголовке запись палитры занимает три байта BGR, в более новых вариантах обычно четыре байта. Коды сжатия выводятся как BI_RGB, BI_RLE8, BI_RLE4 и распространённые дополнительные варианты.

### PNG

Проверяется восьмибайтовая сигнатура. Каждый чанк состоит из длины, типа, данных и CRC. В IHDR ширина и высота хранятся как 32-битные числа big-endian; далее указаны глубина, тип цвета, метод сжатия, метод фильтрации и метод чередования. CRC проверяется для прочитанных чанков. Завершающий IEND обязателен. Глубина bpp вычисляется как глубина одного канала, умноженная на число каналов для соответствующего типа цвета. Для индексированного изображения фактическая глубина пикселя соответствует глубине индекса, а не глубине RGB-палитры.

### JPEG

Парсер читает маркеры и длины сегментов, пока не встретит сегмент SOF с геометрией или данные сканирования. SOF задаёт точность компонента, высоту, ширину и число компонентов. JFIF может хранить единицы разрешения и X/Y density. EXIF может содержать XResolution, YResolution и ResolutionUnit в IFD. После данных изображения проверяется маркер EOI `FF D9`. Сжатие описывается как DCT; различаются progressive и остальные варианты по типу SOF.

### GIF

Распознаются сигнатуры GIF87a и GIF89a. Logical Screen Descriptor содержит размеры и признаки глобальной палитры. Размер палитры определяется packed-полем. Парсер проходит extension-блоки, image descriptor и подпакеты LZW, не декодируя пиксели. Количество кадров определяется по числу image descriptor. Trailer `0x3B` обязателен. DPI стандартным заголовком GIF не задаётся.

### TIFF

Первые байты определяют порядок байтов II или MM. Для классического TIFF проверяется magic number 42 и читается смещение IFD. Каждый элемент IFD содержит тег, тип, количество значений и inline-значение либо смещение. Парсер поддерживает распространённые типы TIFF, цепочку страниц и основные теги ширины, высоты, BitsPerSample, Compression, PhotometricInterpretation, SamplesPerPixel, X/YResolution и ResolutionUnit. Значения разрешения в сантиметрах переводятся в точки на дюйм. Структурные ссылки на полосы и тайлы учитываются как диагностические сведения; сами данные изображения не декодируются.

### PCX

Читается 128-байтовый заголовок. Проверяются manufacturer, encoding и bits per pixel. Размеры вычисляются по координатам xmin/ymin/xmax/ymax включительно. Поля horizontal/vertical screen resolution используются как DPI, если ненулевые. Глубина пикселя определяется произведением BitsPerPixel на число planes. Encoding 1 означает RLE, encoding 0 — отсутствие RLE.

## Производительность

Обход папок выполняется отдельно от GUI. Задачи обработки файлов отправляются в ограниченный `ThreadPoolExecutor`; результаты передаются интерфейсу пакетами. Парсеры открывают файл, читают небольшие заголовки и сегменты и закрывают его, не загружая изображение целиком. Пользователь может отменить обход. Модель `QTableView` хранит результаты и поддерживает сортировку через proxy-модель.

## Обнаружение повреждений и ограничения

Проверяются сигнатуры, границы смещений, размеры структур, корректность ряда обязательных полей, CRC PNG, IEND PNG, EOI JPEG, trailer GIF и структура IFD TIFF. Ошибки доступа отделены от повреждённых файлов и неподдерживаемых форматов. Проверка метаданных не является полной проверкой декодирования изображения: например, IDAT PNG, JPEG entropy-coded data и полосы/тайлы TIFF не декодируются полностью. Некоторые нестандартные варианты форматов могут быть отвергнуты. TIFF BigTIFF не поддерживается. Для JPEG поиск EOI ограничен логикой обработки маркеров и не гарантирует обнаружение всех повреждений потока.
